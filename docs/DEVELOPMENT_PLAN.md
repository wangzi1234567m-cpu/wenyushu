# 开发阶段与验收计划

- 日期：2026-10-24
- 依据：PRD V1.2、SAD V1.0、DELIVERY、OpenAPI 与数据库设计基线。
- 状态：开发计划；不是功能验收记录，也不表示任何阶段已经完成。
- PRD §2.4 的 P0/P1 是功能优先级；本文 P0—P5 是 PRD §14.1 与 DELIVERY 定义的交付阶段。收藏、保存思考、历史每日一问、大规模片语策展不因同名“P1”进入每日一问阶段。

## 1. 顺序与共同门禁

按 P0 → P1 → P2 → P3 → P4 → P5 交付，一阶段一分支一 PR。P3 的业务和代码不依赖 P2；P4 通过端口组合两者。架构保持模块化单体、单一 PostgreSQL 和同仓库 Worker。

每阶段从已验收的最新 main 创建分支；完成实现、自动化测试和 PR 后，由用户人工验收。CI 与人工验收都 PASS 才合并 main，再进入下一阶段。里程碑 Tag 按 DELIVERY 在获授权且验收通过后创建；生产部署单独执行，不由合并自动推定授权。

所有阶段共同要求：

1. 可按 README 启动，第三方依赖可注入 Mock；自动化测试不依赖真实 Key 或外网。
2. 正常、失败、越权、幂等及边界用例按模块覆盖；真实 PostgreSQL 验证数据库约束。
3. 后端测试/lint、前端 lint/typecheck/build、OpenAPI 静态校验和本阶段已实现接口的一致性检查全部成功。未实现的后续接口不伪造为已交付。
4. 界面具备加载、空结果、失败提示和可行的恢复操作；身份授权、输入规模限制、日志脱敏与内容安全随功能交付。
5. 验收记录包含命令、输出摘要、环境、PR、提交 SHA、人工操作及实际结果、迁移说明、风险和回滚步骤。未执行或阻塞的检查不得写 PASS。
6. 契约变化先提出 ADR，经批准后同步 OpenAPI、迁移、前后端 DTO 与测试。待决事项见 `adr/011-prd-contract-clarifications.md`。

## 2. P0：基础工程

分支：`feat/p0-foundation`。目标：无真实模型 Key 也能运行和验证的工程与安全基础。

开发顺序：Next.js/TypeScript、FastAPI/Pydantic 工程 → SQLAlchemy/Alembic → 匿名身份与安全依赖 → 健康检查和统一异常 → Mock 端口 → Compose/Worker 启动入口 → CI 与文档。

| 编号 | 验收标准与证据 |
|---|---|
| P0-01 | Win11 按 README 一条 Compose 命令启动 web/api/worker/postgres；不配置 DeepSeek Key，首页骨架仍可访问，记录启动日志及 HTTP 结果。 |
| P0-02 | 按契约 `/api/v1` 前缀访问 live/ready，依赖正常时 200；数据库不可用时 ready 返回契约规定的失败响应，live 仍反映进程存活。 |
| P0-03 | 匿名凭证随机生成，数据库仅存 token hash；有效 Cookie 重复 bootstrap 保持同一 actor，返回可用 CSRF token；失效和撤销凭证不能继续授权。 |
| P0-04 | 缺失/错误/跨身份 CSRF 与非允许 Origin 的受保护写请求被拒；bootstrap 豁免遵循契约且检查来源。Cookie 安全属性可验证。 |
| P0-05 | 以测试夹具验证授权端口拒绝其他 actor 的资源；不为测试提前开放 P3 会话业务。后续各资源阶段再补 HTTP 越权测试。 |
| P0-06 | Alembic 在空 PostgreSQL 成功升级，重复 upgrade 无重复建表；表、索引、外键、唯一性和 CHECK 与设计逻辑等价，非法数据插入测试确实被拒。 |
| P0-07 | LLM/Search Mock 可替换注入，支持正常/失败场景；统一错误符合 ErrorEnvelope，含 request_id，不泄露堆栈或密钥。 |
| P0-08 | CI 全绿；提交 `.env.example`、启动/停止/测试说明；Git 中无真实密钥、缓存、私人数据。 |

此阶段创建基线所需数据库结构，不实现推荐处理、探索流程、真实聊天或 Handoff。

## 3. P1：每日一问与选项探索

分支：`feat/p1-daily-exploration`。模块：content、exploration、ReadingIntent 端口及首页/探索页面。推荐能力使用明确标识的 Mock。

| 编号 | 验收标准与证据 |
|---|---|
| P1-01 | 首页展示品牌、每日一问、找书与思辨入口；后续功能未完成时入口状态明确，不伪装为可用。 |
| P1-02 | 测试北京时间 23:59:59/00:00:00 边界；同日刷新不换题，跨日新探索换题，旧探索保留原版本。 |
| P1-03 | 修改题目及选项后已有探索仍可按固定版本完成；缺少排期使用审核通过备用题；撤下内容不再用于新探索。 |
| P1-04 | 通常 2—3 步完成，分支按选择变化；非必要偏好可跳过。返回与改答行为须按 ADR 批准方案测试，不能省略 PRD 要求。 |
| P1-05 | 非法选项、跨步骤选项、重复提交、过期探索、他人探索均有自动化断言；并发重复请求不产生重复答案或阅读意图。 |
| P1-06 | 不同理由形成对应阅读意图；完成探索不自动启动推荐，只有明确点击找书才调用 Mock RecommendationPort。 |
| P1-07 | 准备连续 7 天的问题排期及备用题，每题具有分支、主题与审核记录；候选作品不因进入种子数据就标为 verified。 |
| P1-08 | 桌面和手机完成探索主路径；直接进入思辨的上下文交接在 P3 联调验收。 |

覆盖 AC-02、03、04；AC-01、05、17 在后续完整功能中继续验收。

## 4. P2：找书与可信推荐

分支：`feat/p2-book-recommendation`。模块：reading、catalog、LLM/Search 适配、Worker 与找书/结果/详情页面。

| 编号 | 验收标准与证据 |
|---|---|
| P2-01 | 兴趣、学习目标、问题探索三入口均能独立创建意图；题材/风格/难度、基础/目标、问题方向进入对应推荐输入。 |
| P2-02 | 每日一问接入同一推荐端口；不同选择影响推荐理由和方向。用户可看详情、调整偏好、主动换一组，既有任务结果不被覆盖。 |
| P2-03 | 推荐创建返回 202，查询返回任务状态；同 actor 同幂等键同参数复用任务，不同参数冲突；不同 actor 无法访问结果。 |
| P2-04 | Worker 原子领取、租约过期恢复、有界重试；并发 Worker 不重复完成同一任务，进程重启后持久任务仍可推进。 |
| P2-05 | 仅有证据支持的作品可展示为 verified；检查同名书、书名/作者、重要情节、证据地址；同一作品不同译本不得充作不同推荐。 |
| P2-06 | 0/1/2/3 本均有测试：0 本失败并提示恢复，1/2 本按任务结果正常展示，禁止凑数；搜索故障可使用合格缓存，否则明确失败/降级。 |
| P2-07 | 模型非法 JSON、截断、429、超时、搜索失败和无来源全部可 Mock；不编造引文、来源或授权。真实 Provider 接入前核验当时官方能力。 |
| P2-08 | 至少 30 组需求覆盖 PRD §13.1 各类主题，逐条记录书籍事实、内容介绍、偏好匹配、角度、难度和降级结果；已发现缺陷修复或明确阻塞，不能仅记录总通过率。 |
| P2-09 | 每张卡片解释内容、推荐关联及可能获得的视角；合法阅读渠道仅在确认可用时显示；图片和引文有使用依据，无法确认时使用原创说明。 |

覆盖 AC-05—10；推荐举报在 P3 的安全功能中联调，P5 总体验收。

## 5. P3：独立思辨对话

分支：`feat/p3-discussion-runtime`。模块：conversation、discussion、safety 与思辨页面。

| 编号 | 验收标准与证据 |
|---|---|
| P3-01 | 用户可从已有议题、每日一问或自由输入进入讨论；首版精选 15—20 个议题，具备 PRD §9.7 要求的内容与适宜性审核记录。 |
| P3-02 | 多轮讨论正常，测试断言 RecommendationPort 调用次数为 0；推荐服务不可用时讨论仍可运行。 |
| P3-03 | SSE 遵循契约四类事件；不透传 reasoning；未完成回复标失败，不作为已完成历史；断流可读取此前完成消息。 |
| P3-04 | 相同 client_message_id 不重复生成；同会话并发第二次生成返回 CONVERSATION_BUSY；其他 actor 访问返回不泄漏存在性的错误。 |
| P3-05 | 使用可控 token 预算触发摘要，验证关键观点、观点变化、限定条件、未决问题保留；假设不被转写成真实经历；覆盖区间不重复计入上下文。 |
| P3-06 | 摘要失败保留原始消息和旧摘要；模型失败后可以继续聊；刷新在凭证及会话有效期内恢复完成记录。 |
| P3-07 | 输入/输出安全策略与风险测试可运行；显示 AI 标识，消息和推荐举报可提交并有处理入口；日志不保存完整私密对话。 |
| P3-08 | 人工对照 PRD §8.3 评估对话：无机械每轮反问、无强制推荐、无人格诊断或依赖诱导，能澄清、提供不同视角和合理反例；记录对话样例与发现的问题。 |

覆盖 AC-11、12、15、16；桌面/移动恢复体验纳入 AC-17。

## 6. P4：用户主动触发阅读联动

分支：`feat/p4-discussion-handoff`。模块：handoff，调用 conversation/reading 的公开端口。

| 编号 | 验收标准与证据 |
|---|---|
| P4-01 | 第 1 轮及第 20 轮都能主动找书；未点击时不创建 Handoff/阅读意图/推荐任务。 |
| P4-02 | 触发时固定 up_to_seq；触发后发送新消息，任务输入仍严格限于原快照；再次主动触发才使用最新讨论。 |
| P4-03 | 快照端口检查归属；错误 seq/他人会话被拒；相同幂等请求复用任务，不同参数冲突，失败重试不重复创建意图或书单。 |
| P4-04 | 提炼核心问题并减少无关私人信息，不在任务中复制全部聊天记录；跨模块只通过端口访问。 |
| P4-05 | 推荐生成期间可继续聊天；注入推荐超时/失败，原会话仍可发送和接收消息；结果不会修改原消息。 |
| P4-06 | 桌面侧栏、手机抽屉或可返回页面可用；关闭书单仍保留原会话和输入上下文。 |

覆盖 AC-13、14、17，并回归 AC-11、15。

## 7. P5：整体质量与上线准备

分支：`feat/p5-release-hardening`。不借此增加收藏、支付、社区、Android 或大师对话。

| 编号 | 验收标准与证据 |
|---|---|
| P5-01 | PRD AC-01—18 逐项登记，业务主路径和异常矩阵回归通过；未完成项写 FAIL/阻塞，不使用笼统“全部通过”。 |
| P5-02 | 在明确记录的桌面/手机浏览器及尺寸上完成首页、探索、找书、聊天、联动、举报；无阻断操作的遮挡或横向溢出。建议最少验证 390px 与 1440px 宽度。 |
| P5-03 | 记录机器、并发、数据量、模型与网络条件，测量静态接口 p95、聊天首内容时间和推荐耗时。SAD 初始目标分别为 <500ms、<5s、<30s；属于待实测校准的目标，未达到须记录原因并确认调整，不声称已达标。 |
| P5-04 | 测试请求大小、每 actor 限流、成本预算、Origin/CSRF、权限、安全响应头及服务端 Key 隔离；达到上限确实拒绝，日志不包含密钥、Cookie 或原始私密消息。 |
| P5-05 | 模型/搜索不可用、数据库中断、Worker 崩溃恢复均有演练，记录失败表现与恢复操作；无未处理的数据损坏。 |
| P5-06 | 在隔离环境完成备份恢复，核对关键表数量和约束；实际演练代码回滚及迁移前向修复/恢复步骤，记录耗时和数据影响。 |
| P5-07 | 数据保留期限及删除规则经确认后配置并测试；各归属模块清理消息、摘要与关联任务，无遗留私密副本；说明第三方模型处理和备份保留边界。 |
| P5-08 | 成人访问范围、AI 标识、隐私告知、举报处理及内容/图片/引文来源完成核对；PRD 要求的适用上线手续由运营主体提供核验记录，未完成不得公开上线。 |
| P5-09 | 形成发布、回滚、监控和事故处理说明；生产部署需单独授权。30—50 名成年目标用户体验测试是 PRD 的建议验证计划，不虚构参与者或结果，不以点击量代替实际阅读行为。 |

## 9. 验收记录与回滚

每阶段新增 `docs/acceptance/Pn.md`，按上述编号记录 PASS/FAIL/未执行及证据。自动化通过不替代用户人工验收；人工通过不替代 CI。当前文档只定义标准，不生成虚假的测试成绩。

代码回滚优先建立 revert PR；迁移先评估数据兼容性，优先前向修复，必要时按已演练的备份恢复流程处理。禁止未经评估直接 downgrade 或删库。文档阶段的回滚仅撤销本次新增文档，不触及现有基线。
