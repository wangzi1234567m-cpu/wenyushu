# 一、产品概述

## 1.1 产品定位

**问与书是一个以好奇心为起点，连接有趣的问题、自由的思考与真实阅读的 AI 阅读发现产品。**

用户可以从一个关于爱情、友情、家庭、人生意义或世界的有趣问题出发，通过几次简单选择，发现与自身兴趣和思考方向相关的书籍。

用户也可以独立根据阅读兴趣、知识需求或学习目标寻找好书。

此外，产品设有独立的思辨空间，用户可以自由讨论值得思考的问题，在持续对话中理解不同的观点。

## 1.2 产品 Slogan

**从一个问题，走向一本好书。**

辅助表达：

世界很大，值得思考的问题很多，值得读的书也很多。

## 1.3 产品愿景

降低人们发现优质书籍、开始阅读以及接触思想性内容的门槛。

让阅读不再只是一项需要完成的任务，而是由个人好奇心、兴趣和生活体验自然驱动的探索过程。

长期希望形成一个连接阅读、思想与生活的精神文化产品。

## 1.4 核心价值

帮助用户：

1. 发现真正值得思考的问题。
2. 通过轻量选择了解自己当下的兴趣方向。
3. 找到与个人兴趣、经历和目标匹配的真实书籍。
4. 理解一本书的内容，以及为什么值得自己阅读。
5. 在自由讨论中接触不同思想与观点。
6. 自主决定是否继续思考或者开始阅读。

## 1.5 产品设计原则

**问题驱动：** 从现实生活与富有想象力的问题出发，而不是先向用户灌输学科知识。

**轻量交互：** 用户通过少量选择就可以发现书籍，不强制完成复杂问卷。

**思辨独立：** 思辨本身具有价值，不强制引导所有用户进入阅读推荐。

**推荐有据：** 真实书籍、准确介绍、合理解释推荐原因。

**阅读自由：** 尊重文学欣赏、兴趣探索和专业知识学习等不同动机。

**思想开放：** 不将人生议题简单判定为正确或错误。

**技术适度：** 不以 RAG、Agent 框架或者知识图谱的复杂度证明产品价值。

**安全合规：** 从产品设计阶段考虑隐私、AI 内容、版权和内容适宜性。

# 二、首发市场与产品范围

## 2.1 中国大陆首发策略

| 项目 | MVP 决策 |
|---|---|
| 运营市场 | 中国大陆 |
| 平台 | Web 网站，适配桌面与手机浏览器 |
| 后续平台 | Android App |
| 首发人群 | 18岁及以上的阅读与思想探索用户 |
| AI 服务 | 优先评估已完成相应备案的国内模型，重点考虑 DeepSeek |
| 图书推荐 | 模型知识优先，必要时联网搜索与核验 |
| 收费 | 免费，不提供会员及订阅 |
| 账号 | 首次体验不强制注册 |
| 社交 | 不提供公开社区和陌生人私聊 |

## 2.2 三类目标用户

### 问题探索型

用户因为孤独、爱情、自由、命运或人生选择等问题产生好奇，希望寻找相关作品，获得不同的理解。

### 兴趣阅读型

用户想阅读某种题材，例如爱情小说、科幻、悬疑或文学经典，希望按作品风格、阅读难度和情绪氛围获得推荐。

### 目标学习型

用户希望系统了解一门知识或学习某种技能，例如经济学、心理学、写作、商业等，需要根据自己的基础与学习目标找到合适书籍。

三种类型不是永久身份。同一个用户可以在不同时间选择不同的阅读目的。

## 2.3 学龄与年龄规划

长期支持按照小学、初中、高中、大学、成年等阶段进行内容适配。

不同阶段可有不同的问题表达、适宜主题、阅读难度及互动策略。

**MVP 仅面向18岁及以上用户。**

未成年人版本需在满足必要的内容保护、数据与监护要求后另行开发。

## 2.4 MVP 功能范围

| 功能 | 优先级 |
|---|---|
| 首页与每日一问 | P0 |
| 选项式问题探索 | P0 |
| 兴趣找书 | P0 |
| 学习目标找书 | P0 |
| 问题探索找书 | P0 |
| AI 图书推荐及核验 | P0 |
| 思辨空间和连续 AI 对话 | P0 |
| 从思辨会话主动触发书籍推荐 | P0 |
| AI 内容安全、反馈与举报 | P0 |
| 收藏想读书籍 | P1 |
| 保存思考 | P1 |
| 历史每日一问 | P1 |
| 名著金句与片语扩充 | P1 |

## 2.5 当前明确不做

- 九位大师角色对话。
- 大规模大师知识库。
- 未经授权的电子书全文。
- 公开发帖与陌生人私聊。
- AI 情感伴侣。
- 复杂阅读打卡与积分排行榜。
- 付费会员。
- 未成年人开放式 AI 思辨服务。
- 跨会话永久人格画像。
- 完整图书数据库建设。
- 不必要的复杂多智能体系统。

# 三、产品信息架构

## 3.1 一级导航

首发主要提供三个入口：

**首页｜找书｜思辨**

「我的收藏」在 P1 功能实现后再加入正式导航。

## 3.2 首页

首页包括：

1. 问与书品牌名称与 Slogan。
2. 今日一问卡片。
3. 开始探索按钮。
4. 找本好书入口。
5. 思辨空间入口。
6. 精选书籍或文学片语。

今日一问是首页的主要视觉焦点。

## 3.3 核心业务路径

**路径 A：每日一问**

看到问题 → 选择观点 → 选择原因 → 选择阅读偏好（可跳过）→ 推荐相关书籍。

**路径 B：兴趣找书**

选择题材 → 选择风格 → 获得推荐。

**路径 C：学习目标找书**

输入目标 → 确定基础 → 选择学习深度 → 推荐书籍。

**路径 D：问题探索找书**

输入问题 → 理解兴趣方向 → 推荐书籍。

**路径 E：思辨空间**

浏览议题 → 创建对话 → 持续讨论 → 自主结束或继续。

**路径 F：思辨转阅读**

用户主动点击找书 → 自动总结当前讨论 → 推荐相关书籍 → 返回原有会话。

其中，路径 E 是独立的完整体验，不依赖路径 F。

# 四、核心功能一：每日一问

## 4.1 功能目标

每天通过一个有趣、具有情感共鸣或思想冲突的问题激发用户好奇心。

用户经过少量选项选择，就能发现与自己关注方向相关的书籍。

## 4.2 问题示例

**如果你有一种超能力，可以让喜欢的人也爱上你，你会使用吗？**

情境：

你喜欢一个人很久了。某天，你获得一项能力，可以让对方也爱上自己，但这份感情并不是完全出于对方主动的选择。

你会使用吗？

## 4.3 第一轮：表达直觉

- 会，我希望拥有这份爱情。
- 不会，我希望对方自由选择。
- 取决于具体条件。
- 我还没有想好。

## 4.4 第二轮：寻找原因

根据第一轮选择展示不同选项。

例如，选择「不会」：

- 爱应该建立在自由选择之上。
- 我不愿意通过控制得到爱情。
- 我可能无法相信这种感情的真实性。
- 我更想了解得不到回应的爱情。
- 说不清，但直觉告诉我不应该。

选择「会」：

- 爱情值得主动争取。
- 如果两个人最终幸福，过程也许没有那么重要。
- 我不想错过喜欢的人。
- 我想知道被爱和真正的爱究竟有什么区别。

选项不应暗示某种立场在道德上必然更优越。

## 4.5 第三轮：选择阅读方向

可选择：

- 我想看一个相关的爱情故事。
- 我想了解爱情、自由与选择的思想讨论。
- 都可以。

这一轮允许跳过。

## 4.6 推荐结果

根据用户此前选择，生成相关书籍。

书单必须解释：

- 书讲了什么。
- 为什么与用户当前兴趣有关。
- 它可能提供什么新视角。

不同的理由应能影响推荐方向，而不是所有分支都展示相同书单。

## 4.7 交互要求

- 通常2—3步完成。
- 支持上一步和修改答案。
- 非必要步骤可以跳过。
- 不要求用户填写长篇文字。
- 不把选择用于人格诊断。
- 用户可以直接进入思辨讨论。
- 用户明确点击找书后才启动推荐任务。

# 五、每日一问的日历更新

## 5.1 更新规则

每日一问根据日期自动更换，而不是页面每刷新一次就随机生成。

MVP 统一采用北京时间（Asia/Shanghai）。

要求：

1. 当天的问题保持一致。
2. 新日期自动切换问题。
3. 刷新页面不改变当日主题。
4. 进行中的探索不会因跨日自动切换题目。
5. 支持提前安排未来的问题。
6. 缺少排期时使用经过审核的备用问题。
7. 可以撤下有问题的内容。

## 5.2 问题版本管理

每道问题拥有稳定标识与内容版本。

用户开始一次探索后，该次探索使用固定的问题版本。

即使运营人员修改选项，也不能破坏用户正在进行的流程。

## 5.3 内容准备

MVP 上线前至少准备：

- 连续7天的正式问题。
- 若干备用问题。
- 每个问题必要的选择分支。
- 相关兴趣与主题标签。
- 候选参考作品。

首版不依赖 AI 每天自动随机生成未经审核的问题。

# 六、核心功能二：找本好书

## 6.1 定位

让用户从不同阅读目的出发，快速发现适合自己的书。

这一模块不依赖每日一问。

## 6.2 入口 A：兴趣找书

用户说：

**“我想读一本爱情小说。”**

系统可以进一步询问：

- 更希望文学价值较高、语言优美？
- 更希望故事吸引人、通俗易读？
- 想看温柔治愈的爱情？
- 想看现实复杂的爱情？
- 想看带有遗憾的爱情？
- 没有明显偏好？

必要时进一步询问阅读难度或篇幅。

推荐应尊重用户偏好，而不是永远优先推荐最著名的名著。

## 6.3 入口 B：学习目标找书

用户说：

**“我想学习经济学。”**

可以选择：

- 完全零基础。
- 已经了解一些。
- 希望学习专业理论。
- 希望获得实践指导。

推荐应考虑：

- 目标匹配。
- 知识准确性。
- 阅读门槛。
- 先修知识。
- 理论深度。
- 实践价值。

对于专业学习，可以说明适宜的阅读顺序。

## 6.4 入口 C：问题探索找书

用户可以输入：

- 人为什么害怕死亡？
- 我们真正想要什么？
- 人与人之间为什么会走散？
- 什么才算一种自由的人生？

系统应理解问题背后的思想方向，必要时提供少量角度选择，再推荐作品。

# 七、图书推荐机制与内容要求

## 7.1 核心决策

**MVP 不需要先建完整的自有图书库。**

优先使用 DeepSeek 已有的知识提出真实作品候选，必要时利用搜索工具核验。

同时允许复用少量经过核验的书籍资料。

## 7.2 推荐不只进行关键词匹配

例如，问题：

**人终究是孤独的吗？**

若用户认为：

“因为人与人最终都会走散。”

系统应重点理解：

- 宿命。
- 时间。
- 离别。
- 失去。
- 家族命运。
- 关系的有限性。

若用户认为：

“因为没有人能真正理解另一个人。”

则应更关注：

- 理解的边界。
- 自我与他人。
- 精神隔阂。
- 人与社会的疏离。

若用户认为：

“独处是自由的一部分。”

则关注：

- 自我选择。
- 独立。
- 精神自由。
- 独处的价值。

**用户选择的理由比单纯的问题关键词更加重要。**

## 7.3 推荐流程

1. 理解阅读意图。
2. 分析问题背后的主题与思想方向。
3. 结合用户的选项和阅读偏好。
4. 由模型提出候选书籍。
5. 对关键书籍事实进行必要核验。
6. 过滤错误、不合适或缺乏依据的作品。
7. 生成简洁准确的推荐理由。
8. 经后端结果检查后交付用户。

模型应负责语义理解与生成，而实际业务系统负责过程控制、字段检查与结果交付。

## 7.4 搜索与核验

模型可以依靠自身知识产生候选，但不能把自己的判断自动标记为已经验证的事实。

对以下情况应重点核验：

- 冷门书籍。
- 同名或容易混淆的作品。
- 具体作者与出版版本。
- 小说人物及关键情节。
- 原著金句。
- 具体译本。
- 最新出版的作品。

如果不能核实某些具体事实，应降低描述的细节程度、替换候选或说明信息不足。

## 7.5 推荐结果

默认展示1—3本书，优先提供三本具有不同但相关视角的作品。

每本书包括：

**作品基本信息**

书名、作者、必要版本资料。

**书籍内容**

简短介绍故事背景、核心问题或者主要知识内容。

**为什么推荐给你**

明确解释与用户当下选择的联系。

**你可能获得什么**

对阅读体验或新的理解进行审慎描述。

**操作**

查看详情、调整偏好、换一组推荐，以及可用时查看经过确认的合法阅读渠道。

## 7.6 核心质量约束

- 不虚构书名与作者。
- 不编造故事人物及重要情节。
- 不把一本书错误解释为完全不同的思想观点。
- 不用模型自评替代事实核验。
- 不重复将同一作品的不同译本当成三本不同作品。
- 不为了凑足三本而推荐不相关的书。
- 允许只返回两本甚至一本可靠作品。
- 搜索失败时不编造参考来源。
- 不展示未经核验的原著引文。

# 八、核心功能三：思辨空间

## 8.1 功能定位

**思辨空间的主要任务是持续讨论，而不是推荐书籍。**

用户可以围绕爱情、友情、亲情、自由、自我、生死、时间、社会与想象展开对话。

系统帮助用户澄清问题、理解不同立场，并探索其中的价值冲突。

## 8.2 两种进入方式

**从已有议题进入**

用户浏览问题库，选择自己感兴趣的问题。

**自由提出问题**

用户直接输入希望讨论的问题。

用户可以选择快速表达初始立场，也可以直接开始自由聊天。

## 8.3 思辨助手的行为

助手应能够：

1. 理解用户当前观点。
2. 澄清复杂概念。
3. 适当提出启发性追问。
4. 提供不同视角。
5. 举出合理反例。
6. 识别论证中的重要矛盾。
7. 尊重用户自己的判断。
8. 保持连续对话。

助手不应该：

- 每轮机械反问。
- 为了辩论而反对用户。
- 无条件奉承用户。
- 把一种人生观当成唯一正确答案。
- 分析或诊断用户人格。
- 主动制造情感依赖。
- 频繁打断对话推荐书籍。

## 8.4 对话记忆要求

MVP 采用会话级短期记忆。

主要包括：

- 当前议题。
- 最近原始消息。
- 必要的历史摘要。
- 用户明确表达的关键观点。
- 观点变化及重要限定条件。

当对话达到上下文预算时，系统可以压缩较早历史。

压缩后应保留关键观点、讨论脉络与尚未解决的问题。

不能将用户假设的情境错误地当作其真实经历。

原始会话记录和摘要按照适用的数据保留规则管理。

MVP 不默认形成跨会话人格记忆。

## 8.5 会话体验要求

- 可以持续多轮聊天。
- AI 回复以流式方式显示。
- 网络异常时能恢复已经完成的消息。
- 本轮回复失败不会关闭整个会话。
- 用户刷新后仍可在有效期限内恢复讨论。
- 不同用户的会话必须隔离。
- 明确标识 AI 助手。
- 提供举报不当回答的渠道。

## 8.6 从思辨随时推荐书籍

在聊天界面提供：

**「根据我们的讨论找几本书」**

用户可以在任意一轮点击。

系统需要：

1. 获取用户触发时的有效对话快照。
2. 总结讨论中的核心问题和关注方向。
3. 尽可能减少无关私人信息的使用。
4. 生成阅读需求。
5. 调用统一图书推荐能力。
6. 返回相关作品及推荐理由。

**这一操作不得中断原有思辨对话。**

### 桌面端

推荐结果在侧边书单面板显示。

### 移动端

推荐结果可以通过底部抽屉或者可返回页面显示。

### 额外约束

- 用户可以在推荐生成期间继续聊天。
- 推荐依据固定为点击时的对话内容。
- 后续聊天不会悄悄改变已经生成的书单。
- 如果想根据最新讨论重新推荐，需要用户主动触发。
- 推荐服务故障不影响思辨助手继续工作。
- 不因为用户没有点击推荐，就自动调用推荐模型。

# 九、思辨问题内容库

## 9.1 内容原则

问题应当：

- 有趣。
- 有生活感。
- 有明确的冲突。
- 能够产生不同看法。
- 可以浪漫、幽默、荒诞或深刻。
- 具有文学、哲学或知识延伸价值。

不强制每个问题都进行学术式哲学分析。

## 9.2 爱情主题

首批候选：

1. 如果你有超能力，可以让你爱的人也爱你，你要不要使用？
2. 爱是克制，还是放肆？
3. 惊艳时光的回忆是礼物还是诅咒？
4. 要不要跟大数据匹配到的最合适的人谈恋爱？
5. 在一段恋情里，性与爱应该还是不应该分离？
6. 伴侣有异性 Soulmate，我该不该介意？
7. 爱情是人类的必需品吗？
8. 爱情使人趋于浪漫还是趋于现实？
9. 离世爱人的记忆要不要交给 AI？
10. 我们应该不应该提倡恋爱以“接受婚姻的可能”为前提？
11. 如果有一个按钮能知道对方爱你的程度，要按还是不要按？
12. 缺爱与不缺爱的人，谁更懂得爱人？
13. 爱情需要一个特定结局吗？
14. 当爱情变为亲情，是幸福还是悲哀？
15. 恋爱要找相似的人还是互补的人？
16. BE 爱情辩题适合还是不适合让情侣辩手参赛？
17. 在爱情中，有焦虑型依恋倾向的人，安全感更应该由伴侣支持还是自我建立？
18. 谈一场《花束般的恋爱》式的爱情，是圆满还是遗憾？
19. “菀菀类卿”和“兰因絮果”的爱情，哪一种更可悲？
20. “恨海情天”中，是爱大于恨还是恨大于爱？

部分题目涉及文学、影视或网络文化背景，正式展示时需要补充必要说明。

## 9.3 自我与人生

1. 除去优绩和功利的环境之外，你的内心究竟想要什么？
2. 我们真正想要的是幸福、自由还是被认可？
3. 如果没有人评价你，你还会如此努力吗？
4. 人生一定需要明确的目标吗？
5. 如果可以成为任何人，你还会选择成为自己吗？
6. 为什么我们总是在意别人的目光？
7. 人应该努力成为更好的自己，还是接纳现在的自己？
8. 没有世俗意义上的成功，人生是否就是失败？
9. 我们真的能自由决定自己想成为什么样的人吗？
10. 如果提前知道最幸福的人生道路，你愿意知道吗？

## 9.4 生死、时间与意义

1. 面对终将来临的死亡，你会感到恐惧吗？
2. 如果可以永生，你愿意吗？
3. 如果生命只剩一年，你会改变什么？
4. 你愿意提前知道自己的死亡日期吗？
5. 生命是否因为有限而珍贵？
6. 如果可以删除一段痛苦记忆，你愿意吗？
7. 如果人生重新开始，你还会做出同样的选择吗？
8. 人必须留下些什么，才算不虚此行吗？

## 9.5 友情、亲情与人际关系

1. 真正的朋友需要无话不谈吗？
2. 朋友最终走散，是成长的必然代价吗？
3. 父母的期待和自己的人生理想冲突时，应该怎么选择？
4. 我们是否对最亲近的人反而更加苛刻？
5. 被理解与被陪伴，哪个更重要？
6. 好朋友之间应该有秘密吗？
7. 友谊应该主动维系还是顺其自然？
8. 人与人之间能够真正感同身受吗？

## 9.6 想象与思想实验

1. 如果世界上所有人都无法说谎，世界会更好吗？
2. 如果可以读取别人的想法，你愿意吗？
3. 如果有机器能让你永远幸福，你愿意进入吗？
4. 如果复制一个拥有全部记忆的你，谁才是真正的你？
5. 如果所有人都能看到未来，人生还有惊喜吗？
6. 如果可以暂停时间一天，你最想做什么？
7. 如果 AI 拥有与你相同的记忆，它是否应当得到相同尊重？
8. 如果世界上不存在金钱，人们还会为什么努力？
9. 如果可以和十年后的自己交谈，你最想问什么？
10. 如果可以进入一本小说生活一年，你会选择哪本书？

## 9.7 内容上线标准

以上为候选问题池，并非全部需要一次上线。

首版精选15—20个高质量议题，完成：

- 议题标题。
- 引导情境。
- 必要的观点选项。
- 阅读兴趣方向。
- 关联主题。
- 内容适宜性审核。
- 可选的参考作品。

MVP 至少安排连续7天的每日问题。

# 十、文学片语与名著金句

## 10.1 定位

名著金句是帮助用户发现书籍魅力的辅助内容。

主要用于首页精选、推荐结果和书籍详情。

不单独建设金句社交平台。

## 10.2 内容要求

每条正式引用应包含：

- 真实原文。
- 作者。
- 作品。
- 必要的译者、版本与出处。
- 简短的解读。
- 关联书籍。

## 10.3 内容质量与版权

- 不伪造原著金句。
- 不断章取义。
- 不将 AI 生成文案冒充原文。
- 不在没有适当使用依据的情况下大量转载受保护文字。
- 原著的公版状态与现代译文版权分别判断。
- 封面等图片须具有合法使用依据。

若无法确认原文真实性或合法展示条件，可以采用原创主题说明替代。

大规模片语策展放在 P1 阶段。

# 十一、用户数据与安全要求

## 11.1 匿名使用

MVP 的核心体验不强制注册。

但系统仍需保证：

- 用户之间的会话隔离。
- 对个人思辨记录的访问控制。
- 匿名凭证的安全性。
- 在有效期限内可恢复会话。
- 相关信息能够按照适用规则删除。

不允许仅凭一个用户自行输入的会话 ID 获取其他人的聊天内容。

## 11.2 数据最小化

当前需要处理的数据包括：

- 用户本次选择的问题。
- 当前阅读意图。
- 必要的思辨消息。
- 推荐结果与必要的核验状态。
- 必要的匿名身份信息。
- 安全和错误处理信息。

不默认建立长期个人情感或心理画像。

## 11.3 思辨数据

历史上下文与滚动摘要仅用于实现本次会话的持续性。

不能将讨论中的假设推断为用户现实生活的事实。

用户应能够知晓对话数据的保存与第三方模型处理方式。

## 11.4 内容安全

需要具备：

- 输入内容安全处理。
- AI 输出安全检查。
- 不当内容反馈与举报。
- 异常生成处理。
- 必要的安全日志。
- 对高风险情境的适当回应。

思辨助手不是医疗服务、心理诊断工具或情感伴侣。

## 11.5 中国大陆公开上线条件

根据实际运营主体和业务形态，完成适用的：

- 网站 ICP 备案或相关许可。
- 公安联网备案义务。
- 生成式 AI 服务相关登记、备案或安全评估。
- 个人信息保护要求。
- 内容治理与 AI 生成内容标识。
- 著作权和特殊内容业务资质核查。

开发完成不代表可以不经必要手续直接公开运营。

# 十二、异常处理与用户体验

真实产品需要能够处理非正常流程。

| 异常情况 | 产品应有的表现 |
|---|---|
| 每日问题未配置 | 使用备用的审核通过问题 |
| 当前问题发生修改 | 保持已有探索使用原问题版本 |
| 用户重复提交 | 不重复创建不必要的任务 |
| 模型调用超时 | 保留已有状态，提示重试 |
| 推荐只有两本可靠书籍 | 正常展示两本 |
| 无法找到可靠候选 | 提示调整条件或稍后重试 |
| 图书搜索故障 | 尝试合格缓存或明确降级 |
| 思辨回复中断 | 保留已完成聊天记录 |
| 思辨长对话需要压缩 | 维持关键观点与讨论连续性 |
| 推荐联动失败 | 原有思辨会话继续正常使用 |
| 用户访问他人数据 | 拒绝访问 |
| 内容存在明显安全风险 | 按安全规则进行处理 |

页面需要有清晰的加载状态、空结果、错误提示和恢复操作。

## 13.1 推荐质量测试

至少准备30组不同需求。

覆盖：

- 爱情小说。
- 严肃文学与通俗文学。
- 孤独与宿命。
- 自我探索。
- 亲情友情。
- 生死与人生意义。
- 想象类主题。
- 专业知识学习。
- 实用工具书。
- 冷门兴趣与模糊需求。

需要验证：

1. 真实书籍。
2. 内容介绍正确。
3. 用户偏好匹配。
4. 推荐角度合理。
5. 阅读难度适配。
6. 失败后能正常降级。

## 13.2 用户体验测试

首轮建议邀请30—50名成年目标用户。

重点观察：

- 今日一问是否吸引点击。
- 用户是否愿意完成选项。
- 推荐书籍是否引起兴趣。
- 用户是否查看书籍详情。
- 思辨讨论是否具有独立价值。
- 用户是否希望继续讨论。
- 用户是否产生真实的阅读行动。

需要区分：

**感兴趣 → 想读 → 查找书籍 → 真正开始阅读。**

不把单纯点击当作完成阅读推广。

# 十四、开发阶段与未来扩展

## 14.1 分阶段交付

| 阶段 | 开发内容 | 验收重点 |
|---|---|---|
| P0 | 基础工程与开发环境 | 前后端运行、数据库迁移、基础安全、Mock 与 CI |
| P1 | 每日一问与选项探索 | 日期、版本、问题分支、阅读意图 |
| P2 | 找书与推荐 | DeepSeek、按需核验、结果页和异常处理 |
| P3 | 思辨模块 | 连续对话、流式输出、上下文压缩、会话恢复 |
| P4 | 思辨与阅读联动 | 固定会话快照、主动找书、独立故障处理 |
| P5 | 上线准备 | 集成测试、安全、性能、部署与合规门禁 |

每个阶段都应能够独立验收。

## 14.2 Git 与质量管理

统一开发流程：

**Feature Branch → 开发 → 自动测试 → 人工验收 → Pull Request → CI 通过 → 合并 main → Git Tag**

要求：

- 不直接在 `main` 开发。
- 每一阶段使用独立功能分支。
- 本阶段验收不通过，不开始下一阶段。
- API 或数据表变更必须同步修改契约与测试。
- 不允许直接提交密钥及私人用户数据。
- 不随意执行破坏性 Git 操作。
- 重要架构调整记录变更原因及影响。

详细操作以 `docs/DELIVERY.md` 为准。

## 14.3 未来 Android

后续 Android App 应尽量复用已经验证的后端业务能力，避免重复开发另一套推荐和思辨逻辑。

移动端需要另外完成适用的备案、应用商店审核、设备适配和隐私要求。

## 14.4 未来大师对话

未来可以重新开发原有九位大师的思想对话功能。

其业务功能与思辨助手不同，但可以复用通用会话、消息、上下文管理和模型调用能力。

大师专属的角色设定、著作知识来源和引用核验规则应独立维护。

**未来能够扩展，并不意味着 MVP 必须提前开发大师模块。**

## 14.5 未来年龄适配

在满足适龄内容和相应保护要求后，可扩展：

- 小学阶段问题。
- 初中阶段问题。
- 高中阶段问题。
- 按阅读能力而非仅按年龄推荐书籍。

不得仅通过修改提示词就认为已经完成未成年人服务合规。

## 14.6 未来商业化

产品价值得到验证后，探索：

- 订阅增值服务。
- 阅读与教育机构合作。
- 合法图书渠道合作。
- 专题化阅读服务。

MVP 不开发支付与会员系统。

# 十五、最终产品定义

**产品名称：** 问与书（暂定）

**产品定位：** 以问题激发好奇，以思辨打开视角，以好书延续探索。

**首发市场：** 中国大陆。

**首发平台：** Web 网站。

**首发用户：** 18岁及以上。

**核心模块：**

1. 每日一问。
2. 找本好书。
3. 思辨空间。

每日一问通过选项发现阅读兴趣。

找本好书满足用户自主的兴趣、学习目标和问题探索需求。

思辨空间提供独立的连续思想对话，用户可以随时主动触发相关书籍推荐，但不必这样做。

**产品不以 AI 技术复杂度作为价值证明，而是关注：用户是否经历了有价值的思考，以及是否因此发现真正想阅读的作品。**

最终希望带给用户的感受：

**“一个好问题让我开始思考，一本好书让我愿意继续探索。”**
