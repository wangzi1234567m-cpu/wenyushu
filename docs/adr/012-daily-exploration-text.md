# ADR-012：每日一问的补充表达与可恢复阅读意图

- 状态：已批准实施；依据 2026-10-27 用户明确要求实现本方案。
- P0 前置验收：用户在本次会话明确确认通过；远端合并基线仍需核对补齐。
- 范围：P1，选项加可选补充，真实模型与检索留 P2。

## 决策

1. ExplorationAnswer 增加可选 supplementary_text，最多 300 字符，空白归一为 null；选项仍必填，文本不改变 P1 分支。
2. ExplorationState 增加可选 answers 数组，服务端始终返回当前身份已提交的答案；记录增加可选 step_prompt/option_label 供刷新后的可读展示，提交接口仍只接受原答案字段；旧客户端兼容。
3. content.exploration_answers 增加可空 varchar(300) 列；唯一 Owner 为 exploration，不迁移 schema。
4. reading.intents 对 daily_question 的非空来源增加 actor/source/ref 部分唯一索引。ReadingIntentCommand 按来源幂等创建，重复重试返回原 ID。
5. 相同步骤、相同归一化答案重试复用；不同答案 409。改答通过新建同版本探索并重放有效前缀，旧意图和书单不变。
6. 答案先提交；阅读模块独立提交意图；探索最后关联并完成。中断可按来源恢复；不在锁住探索事务时调用其他模块，不跨模块访问仓储。
7. 已发布题目版本不可原地更新，由内容维护命令创建新版本；流程 JSON 经带 schema_version 的模型校验。每条路径 2—3 步，偏好可跳过。
8. P1 Mock 只匹配固定样例，样例的事实核验必须有实际来源。不存在合格样例就失败，不伪造 verified。自动化只用隔离测试夹具，不以测试夹具充当用户书目证据。

## 同步范围与风险

同步 SAD、OpenAPI、设计 DDL、Alembic 0002、ORM、前后端 DTO、契约和并发/重试测试。保留 0001 不变。P1 用户输入不进入 LLM/Search，无长期人格记忆；补充内容不进入日志，React 按普通文本渲染。

新增列向后兼容；迁移降级会丢失补充文字，仅用于可丢弃测试库。实际数据优先前向修复。P1 中回到 0001 必须先回退应用并备份。
