# ADR-015：每日一问中的案例、双向反问与思想总结

- 日期：2026-11-01。
- 状态：按用户明确要求实施；行为基线为 [Daily Question AI Behavior Policy](../policies/DAILY_QUESTION_AI.md)。
- 范围：现有DiscussionPolicy、每日一问共享讨论输入区、回归和质量记录。不新增API、字段、迁移、推荐/检索或业务阶段。

## 决策

保留共同思考式讨论，增加daily-debate-v1策略。只有服务端探索快照中存在question_version_id时才注入每日一问额外规则；一般讨论不注入这段策略。历史每日一问会话恢复也使用当前规则，题目版本和已保存历史不改写。

每轮只选择一个主要推进点，适时用贴近生活的情境、反例或思想实验，必要时提出一个边界问题；不强迫每轮提问、二选一或辩赢。先正面回答用户反问，承认类比局限及有效反例，尊重不确定、改口、疲惫或不要追问。改变题设必须明确标为对照，虚构情境标为假设；未经核验的心理/医学解释不能为论证背书。

结束时可在正常回复中整理思想总结，区分用户明确立场和AI其他视角，用户通过下一条消息请求修订，再手动收藏确认版本。不是直接编辑消息/收藏记录，也不新增允许客户端改写原话的接口。主动找书时仅整理四项讨论线索，不创建推荐任务或声称已核验作品；真实推荐仍留既定阶段。

输入区新增“用案例继续”“我想反问”草稿入口，仅填入可编辑输入框，不自动发送；输入框有内容时禁用入口，避免覆盖草稿。继续复用已有消息API、身份/CSRF、SSE、历史/摘要、收藏与推荐占位入口。前端按钮不生成固定AI回复。

## 备选与边界

不引入独立辩论Agent、胜负评分、强制正反方轮换、问题生成API或额外模型调用。用户要求的是共同探索中的双向质疑，现有策略和消息流足够表达。

ConversationRuntime仍只负责通用历史、记忆、消息与流式调用；不在运行时中嵌入每日题目规则，不增加Discussion到Recommendation的依赖。现有会话policy_version记录基础discussion-v2；daily-debate-v1是按当前探索上下文动态追加的策略标识，不冒充新建数据库版本。

## 验证与回滚

自动化验证最终LLM输入包含每日策略、原始选择及用户反问，非每日讨论不含额外策略，刷新/幂等重放不增加调用；已有安全和隔离测试回归。浏览器验证两种草稿可改写、不会自动发送、不覆盖非空输入、反问发送与刷新恢复。真实模型采用合成背景连续试答，不读取私人对话，不将Mock输出当成语义质量证明。

回滚撤销本PR提交并重启后端/重新构建前端；无迁移、无数据回滚。现有原消息、摘要、收藏保持不动，不降级0004、不删除数据卷。
